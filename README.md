# Kelly Portfolios

An early-stage research application for position sizing and asset allocation. The Python
workspace asks which return sources and implementation choices can improve a stated
investor's portfolio; the static Astro site presents the current interpretation, with
Solid islands where a reader can type something.

The project is deliberately provisional. Results are scoped to their source, design,
window, benchmark, and investor assumptions. A null or prior decision does not close a
research family: exploration is cheap, while stronger publication and allocation claims
require stronger evidence.

## Current position

The dependable findings are implementation facts: hold low-cost diversified funds, choose
the equity share from the investor's real constraints, place holdings and tax lots
deliberately, and avoid unnecessary trading. Their value is conditional on the investor's
actual holdings, accounts, taxes, embedded gains, and cash flows.

No strategy has yet earned a general promotion over a cheap index. That is not evidence
that none can. Several tests could not resolve the effect that mattered, or asked the
question under a load-bearing funding rule. Trend is the strongest current diversifier
candidate because research series, independent constructions and live funds agree more on
its direction and equity relationship than on magnitude; its crisis dependence, product
survival, financing, tax and method drift remain unresolved.

## Workspaces

### Client

Node 22 and pnpm 10. It calls no API, holds no keys, ships no return series, and keeps
reader inputs in browser storage. Every page is HTML on disk and readable with JavaScript
switched off; [`docs/deploying.md`](docs/deploying.md) covers publishing it.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm biome check
pnpm typecheck
pnpm test
pnpm lint:prose
pnpm lint:figures
pnpm build
```

Research facts rendered by the client live in `src/content/` with provenance and status.
Closed-form arithmetic in `src/lib/` is tested against fixtures generated by the research
workspace. Anything that searches a weight space stays in Python; no optimiser ships.

The site publishes answers, not working notes. `docs/research/` and `docs/decisions/` are
the record a figure's `docPath` points at; the build checks that the file and heading it
names exist, and never renders the path. See
[decision 0011](docs/decisions/0011-the-site-publishes-answers-not-notes.md).

### Research

Python 3.12 and `uv`.

```sh
cd research
uv sync --extra dev
uv run pytest
uv run mypy
uv run ruff check
```

See the [research README](research/README.md) for the data, experiment, artifact, and ledger
contracts. Detailed experiment results live in committed `research/artifacts/*/summary.md`
files; syntheses link them instead of duplicating full tables.

## Repository map

- `research/`: numerical core, data provenance, inference, frozen specifications, ledger,
  and result artifacts.
- `docs/research/`: current interpretation by research question. Not published.
- `docs/decisions/`: rationale for durable choices, with live and historical records
  separated in the [decision index](docs/decisions/README.md). Not published.
- `src/content/`: typed, sourced client research content.
- `src/lib/`: ported arithmetic and generated fixtures.
- `src/components/`: application UI.

`sst.config.ts` references `./infra/*` and `functions/`, which are not in version control.
Do not “repair” deployment by deleting those imports. The client itself builds as a static
site and needs no environment variables. `scripts/seed-database.ts` creates an unseeded
synthetic random walk; its output is not market data.

The deployed site is <https://kellyportfolios.com/>.
